# Team Data & API Contract: Honeytoken-Based Insider Threat Detector

This document serves as the foundational agreement across all sub-teams (Backend Architecture, Listener Engine, Validation & Docs, and Decoy Templates). All components must adhere strictly to these models, route structures, and response shapes.

---

## 1. Route Namespace & Prefixes

- **API Base Prefix:** `/api/v1`
  - All administrative, configuration, and data-access endpoints reside under `/api/v1`.
- **Public Beacon Prefix:** `/beacon`
  - Telemetry capture endpoints reside at `/beacon/{token_id}`.
  - **Security Rule:** This route is *intentionally unauthenticated* so decoy tracking pixels and rogue requests can execute cleanly without HTTP 401/403 interruptions.

---

## 2. Standard API Response Envelope

All endpoints returning JSON under `/api/v1/*` must follow this standardized envelope:

### Success Response (`status = "success"`)
```json
{
  "status": "success",
  "data": {
    "token_id": "9b1deb4d-3b7d-4bad-9bdd-2b0d7b3dcb6d",
    "name": "AWS Production S3 Access Key",
    "token_type": "api_key",
    "criticality": 45,
    "status": "active",
    "beacon_url": "http://127.0.0.1:8000/beacon/9b1deb4d-3b7d-4bad-9bdd-2b0d7b3dcb6d",
    "created_at": "2026-09-02T18:30:00Z"
  },
  "error": null
}
```

### Error Response (`status = "error"`)
```json
{
  "status": "error",
  "data": null,
  "error": "Honeytoken with ID 9b1deb4d-3b7d-4bad-9bdd-2b0d7b3dcb6d was not found or is revoked."
}
```

## 3. Data Entities & Field Contracts

### 3.1 `HoneyToken`
Represents an individual deployed deception asset.

| Field Name | Type | Constraints / Allowed Values | Description |
| :--- | :--- | :--- | :--- |
| `token_id` | `UUID` (String) | Primary Key, Auto-generated (UUIDv4) | Unique tracking identifier for the decoy |
| `name` | `String(100)` | Required, non-empty | Human-readable label (e.g., "HR Salary Canary") |
| `token_type` | `String(20)` | `api_key`, `canary_doc`, `db_record` | Category of the honeytoken asset |
| `criticality` | `Integer` | Range `1` to `50` (inclusive) | Baseline weight representing asset sensitivity |
| `status` | `String(20)` | `active`, `revoked` (Default: `active`) | Operational status of the honeytoken |
| `description` | `String(255)` | Optional | Contextual notes about asset purpose |
| `placement_location` | `String(255)` | Optional | Where token is planted (e.g., `s3://internal-docs`, `.env`) |
| `created_at` | `DateTime` | UTC Timestamp (Default: `utcnow`) | Creation timestamp |
| `updated_at` | `DateTime` | UTC Timestamp (Auto-updating) | Last modification timestamp |

### 3.2 `TokenTrigger`
Logs each access attempt against a deployed honeytoken.

| Field Name | Type | Constraints / Allowed Values | Description |
| :--- | :--- | :--- | :--- |
| `trigger_id` | `UUID` (String) | Primary Key, Auto-generated (UUIDv4) | Unique event identifier |
| `token_id` | `UUID` (String) | Foreign Key -> `honey_tokens.token_id` | Linked honeytoken |
| `source_ip` | `String(45)` | IPv4 / IPv6 string | Extracted requester IP address |
| `user_agent` | `String(500)` | Optional | Extracted `User-Agent` HTTP header |
| `headers` | `JSON` | Key-value dictionary | Sanitized HTTP request headers |
| `triggered_at` | `DateTime` | UTC Timestamp (Default: `utcnow`) | Time beacon was fired |

### 3.3 `AlertLog`
Represents the triage output generated by the dynamic risk-scoring engine.

| Field Name | Type | Constraints / Allowed Values | Description |
| :--- | :--- | :--- | :--- |
| `alert_id` | `UUID` (String) | Primary Key, Auto-generated (UUIDv4) | Unique alert identifier |
| `trigger_id` | `UUID` (String) | Foreign Key -> `token_triggers.trigger_id` | Associated trigger event |
| `severity` | `String(20)` | `Low`, `Medium`, `High`, `Critical` | Triage classification |
| `risk_score` | `Float` | $\ge 0.0$ | Computed risk value |
| `details` | `JSON` | Dict (multipliers, hour flags, frequency) | Score breakdown factors |
| `created_at` | `DateTime` | UTC Timestamp (Default: `utcnow`) | Alert creation timestamp |

## 4. Beacon Telemetry Contract

- **Endpoint:** `GET /beacon/{token_id}`
- **Behavior:**
  - Lookup `token_id`. If token exists and `status == "active"`, create and commit a `TokenTrigger` record.
  - If token does not exist or `status == "revoked"`, still return the 1x1 transparent GIF (silently ignore or log warning) so clients never receive broken image indicators or error popups.
- **HTTP Response:**
  - **Status:** `200 OK`
  - **Content-Type:** `image/gif`
  - **Cache-Control:** `no-cache, no-store, must-revalidate`
  - **Body:** Standard 43-byte base64-decoded transparent 1x1 GIF (`R0lGODlhAQABAIAAAAAAAP///yH5BAEAAAAALAAAAAABAAEAAAIBRAA7`).
